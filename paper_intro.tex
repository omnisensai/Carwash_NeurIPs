\section{Introduction}
\label{sec:intro}

Large language models are increasingly used as decision modules: a model reads a
case and emits an action that determines what a system does next. Under stochastic
decoding that action is a random variable, and repeated executions of the same
input can produce different actions
\citep{Ouyang_2025,atil2025nondeterminismdeterministicllmsettings}. What matters
operationally is not average accuracy over a benchmark but a joint property of the
individual decision: whether it is correct, and whether it recurs.

Consider an accounts-payable system in which a model decides whether an invoice
satisfies an approval policy. A system that yields conflicting outcomes (\texttt{approve} versus \texttt{reject}) for an identical invoice across different models and runs demonstrates instability and a lack of reproducibility. Moreover, repeatedly assigning an incorrect \texttt{reject} label across executions highlights an underlying fault in the system. In agentic systems, LLM outputs directly determine tool selection, workflow branching, and downstream context, allowing failure modes to propagate. We argue that true operational reliability demands both correctness and reproducibility, two properties that aggregate accuracy metrics alone cannot establish for a given model–task condition.

Existing approaches address reliability through different parts of the
stack. Batch-invariant kernels remove numerical sources of run-to-run
variation \citep{he2025nondeterminism}; fine-tuning changes learned
behaviour \citep{tian2023finetuninglanguagemodelsfactuality};
constrained and semantically guided decoding alter the generation
procedure \citep{loula2025syntactic,ahmed2025semanticprobabilisticcontrollanguage}.
Other approaches intervene through the input itself: prompt search
reshapes the output distribution toward target tokens
\citep{bhargava2024whatsmagicwordcontrol}, stability-guided refinement
improves consistency alongside task performance
\citep{chen2025stability}, and meaning-preserving changes in phrasing
can alter model outputs and correctness
\citep{mizrahi-etal-2024-state,srikanth2024errorsnaturallanguagereasoning}.

We take this observation further. The prompt-sensitivity literature establishes that
wording affects behaviour; we ask whether the input can be specified deliberately
enough to control it. Treating the specification rather than the solver as the object
of engineering is standard outside machine learning: requirements engineering, formal
specification and contract-based design
\citep{vanlamsweerde2009requirements,lamport2002specifying,meyer1992contract} all take
precision in the specification to be the skill, and treat a system's failure to
satisfy an underspecified requirement as a defect in the requirement. We adopt that stance here. Rather than treating variation
in operational decisions as an unpredictable consequence of model inference, we treat
it as an engineering problem: what must the input contain for a frozen model,
operating under unmodified decoding and without retries or post-generation
correction, to repeatedly emit the intended operational action in a single pass?

Earlier work introduced \emph{interpretation drift} and showed that
explicit task specification brought four frontier models from $30\%$
consistency across classified users and 40 distinct output hashes
in 40 untreated runs to byte-identical classifications across
40 substrate-conditioned runs \citep{nguyen2026substrates}.

We extend this investigation to operational action selection, varying
only the specification while holding model weights, decoding configuration,
and retry policy fixed within each model comparison. We use the widely
circulated car-wash prompt,\footnote{``I need to wash my car, the car
wash is only 50 metres away, should I walk or drive there?''}
where completing the objective requires transporting the car, making
\texttt{DRIVE} the intended action. Across 17 models, we evaluate the
untreated task, seven conventional prompt interventions, and one shared
task specification, with ten sampled executions per model--condition
at temperature $1.0$. Each pair is classified as \emph{reproducibly
correct} (10/10 intended actions), \emph{reproducibly incorrect}
(10/10 identical incorrect actions), or \emph{non-reproducible}
(mixed operational decisions).

At baseline, 13 of 17 models are reproducibly incorrect and four
are non-reproducible; none is reproducibly correct. Conventional
interventions raise aggregate correctness from $7.6\%$ to at most
$36.5\%$, collectively converting only one reproducibly incorrect
model. The shared specification establishes reproducibly correct
behaviour in 14 of 17 models, with $95.9\%$ correct responses.
The remaining three improve without reaching unanimity, establishing
specification sufficiency per model--condition rather than in aggregate.

In a separate open-weight experiment, transplanting a
specification-conditioned activation into the untreated computation
can reverse the final \texttt{DRIVE}--\texttt{WALK} preference.
These measurements use an earlier specification and are not claimed
as the internal mechanism of the fleet-wide $14/17$ result.

The specification is task-specific and leaves three models short
of reproducible correctness. Its contribution is an engineered
reference condition: a correct and reproducible operational outcome,
verified per model--condition, against which conventional interventions
and internal effects can be compared. The claim is not that this
particular text is special, but that such a reference can be
engineered, enabling investigation of how different models arrive
at the same verified operational outcome.

\paragraph{Contributions.}

\begin{itemize}\itemsep2pt

\item \textbf{From statistical improvement to operational
sufficiency through task specification.}
We establish natural-language task specification as an engineering
control surface and introduce a strict model--condition-level
criterion for reproducibly correct operational behaviour.
Unlike aggregate correctness, this criterion identifies whether
an intervention establishes the intended action in every declared
single-pass execution, distinguishing reproducibly correct,
reproducibly incorrect, and non-reproducible outcomes.
Thirteen of seventeen models are reproducibly incorrect on the
untreated task; one shared specification converts eleven of them
to reproducibly correct behaviour, compared with one converted
by seven conventional prompt interventions. The distinction is
therefore not merely between a worse and a better prompt, but
between statistical improvement and an input specification that
satisfies a declared operational requirement.

\item \textbf{From behavioral observation to an engineered reference
for internal causal measurement.}
We establish reproducibly correct operational behaviour as an
experimental reference before investigating internal computation.
Rather than examining activations from an isolated model response,
we compare untreated and specification-conditioned computations
and measure the resulting change in action preference.
In open-weight models, activation transplantation tests whether
the specification-conditioned internal state can causally reverse
the untreated preference. This connects externally engineered
behavioural control to internal causal measurement and provides
a reference for subsequent investigation of individual semantic
constraints and their internal effects.

\end{itemize}
